## Adapter: the CLIMADA pipeline regenerates the thesis event-loss table

Generated by `packages/climada/scripts/thesis_adapter_parity.py` (MAR-20) in the CLIMADA pixi env. The adapter (`parametric_insurance_design_climada.pipeline.build_eventset`, the port of the thesis `src/CLIMADA/engine.py`, MAR-73) builds the thesis portfolio from `packages/climada/configs/thesis.yaml`: the 9 Miami assets on the IRIS North Atlantic 10,000-year catalogue. Its EventSet is compared with the parity fixture `parity/tests/data/thesis_eventset`, the thesis event-loss table (`data/output/climada_transformed_loss_data.csv`, SHA256 `8513f5fefdcf6686207df575e6a89d576e5ed935f71b652b4045229caf23ff68`, MAR-9), not with the thesis `engine.py` outputs, which go to other paths (known issue C4). Matrices are compared as IEEE 754 binary64 bytes; the issue's tolerance is 1e-6 relative.

**Result: bit-identical.** The adapter regenerates the thesis input: the same event IDs in the same order, the same years, rates and locations, and `index` and `loss` bit-identical in all 109,026 cells. Only the metadata differs (below).

### Inputs and build

- Catalogue: `IRIS_NA_10000Y_merged.txt`, SHA256 `7f7b224d87db743b5653ebfaa8d9ed1e9e8e7cffc1483643fc9a085f155606bd`, 67,506 storms, 1,687,818 track points.
- Storms within 500 km of an asset: 6,057; skipped (fewer than two track points): 0; rows: 6,057, of which 4,762 are zero at every asset (kept, as in the fixture).
- Wind: model H08, intensity threshold 17.5 m/s (winds below it are stored as 0, as in the fixture), `max_dist_eye_km` 300, `max_latitude` 61, `max_dist_inland_km` off. Impact function: Emanuel (2011) USA (`v_thresh` 25.7, `v_half` 74.7 m/s).
- Runtime: 55 s on Darwin arm64 (Python 3.12.15, numpy 2.3.5).

### Differences in setup, with the same result

- **CLIMADA version.** The thesis ran CLIMADA 6.0.1 (`climada_env.yml` of the thesis repository); the adapter runs CLIMADA 6.1.0 (`packages/climada/pixi.toml`). The comparison above holds across the two versions.
- **Distance to the coast.** The thesis used CLIMADA's default inland cut-off (`max_dist_inland_km` 1000 km). The adapter switches it off by default (`wind.max_dist_inland_km: null` in `configs/thesis.yaml`), because CLIMADA's default would download a 300 MB distance-to-coast raster outside the checksummed downloads. The nine Miami assets lie within a few tens of kilometres of the coast, far inside 1000 km, so the cut-off removes no wind there; the comparison above confirms it for this portfolio.

### Metadata

Only descriptive text and provenance differ: the fixture describes and records the thesis CSV it was converted from, the adapter its own build (CLIMADA version, catalogue checksum, parameters). Metadata fields that differ: `hazard.release`, `index.definition`, `provenance.producer`, `provenance.source_checksums`, `scenario`, `transforms`. The content hashes (`EventSet.content_hash`, which covers the metadata) therefore differ:
