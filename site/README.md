# site/

The project website: interactive explorers of the payout design, and the posts. It is a **skeleton** (MAR-201): a home page, an empty post listing with an RSS feed, and one placeholder explorer page on thesis-fixture data.

- The stack is decided: Quarto with Observable JS (OJS), deployed to GitHub Pages ([ADR 0003](../docs/adr/0003-website-stack.md)). The site is https://marc272.github.io/parametric-insurance-design/.
- The site reads bundles exported from the result store and never runs an optimisation itself ([`docs/SPEC.md`](../docs/SPEC.md) §4). The pages read the committed fixtures under [`fixtures/`](fixtures/README.md) for now; the explorer bundle that published pages will read is built by the Site workflow (see "Bundles" below).
- Everything published here follows the publication rule in [`AGENTS.md`](../AGENTS.md).
- Licence: BSD-3-Clause, under the repository's [LICENSE](../LICENSE). The fixture data are CC-BY-4.0 ([`fixtures/README.md`](fixtures/README.md)).

The repository's [README](../README.md) has the project's status.

## Layout

| Path | What it is |
|---|---|
| `_quarto.yml` | The Quarto project: website, navbar, light and dark themes (`flatly`, `darkly`), the pinned Quarto version (`quarto-required`) and the bundles copied into the site (`resources`) |
| `index.qmd` | Home page |
| `explorers/alpha-beta.qmd` | The α/β payout explorer, a placeholder on the `fixtures/thesis-explorer/` bundle: α or β of the weighted-CVaR objective → the step payout and the exceedance curves, with the setup of every number read from the bundle's manifest |
| `blog/index.qmd` | The post listing and its RSS feed (`blog/index.xml`). Posts go under `blog/posts/` |
| `styles/site.scss` | Small additions to both themes: chart backgrounds, phone-width inputs, the setup table |
| `fixtures/` | The committed bundles and the config of the explorer bundle ([`fixtures/README.md`](fixtures/README.md)) |
| `configs/explorer.yaml` | The config of the explorer bundle that the Site workflow solves and exports on every build (MAR-208; "Bundles" below) |

Explorer pages use Observable Plot pinned in the page (`@observablehq/plot@0.6.17`, from jsDelivr), because Quarto's built-in `Plot` follows the CDN's latest release. Quarto's OJS runtime reads the Arrow files with apache-arrow 9.

## Bundles

| Bundle | Where it comes from | Publishable? |
|---|---|---|
| `fixtures/thesis/`, `fixtures/thesis-explorer/` | Committed; regenerated by hand ([`fixtures/README.md`](fixtures/README.md)) | No: in sample, event-conditional basis |
| `bundles/explorer/` (in the built site only) | Solved and exported by the Site workflow on every build from [`configs/explorer.yaml`](configs/explorer.yaml) on the committed thesis parity event set (MAR-208, [ADR 0003](../docs/adr/0003-website-stack.md) "Where bundles come from in CI") | Its `eval_split = "test"` rows: out of sample, annual basis |

The explorer bundle is the one the payout explorer (MAR-54) reads: the thesis portfolio, the individual scope, the MSE, E[U] and weighted-CVaR objectives and their α, β and budget-loading (κ) sweeps, under pure pricing, on a holdout split (years 0–6,999 train, 7,000–9,999 test). For CI it is reduced: one scope, no bootstrap intervals, coarse sweep grids. The config lists every reduction, and the bundle's label (the config's description, `manifest.json` → `label`) repeats them. About 2.7 MB in 15 files.

- **Publication rule.** A holdout run stores its KPIs and exceedance curves on the train years (`eval_split = "train"`, in sample) and on the test years (`"test"`, out of sample). A published page shows the `"test"` rows only, and states the setup from `manifest.setup`.
- **Checks.** Before the Pages artifact is uploaded, the build checks every file against the manifest's SHA-256 and size, that the bundle directory holds no other file, that the manifest's config hash is that of `configs/explorer.yaml`, and the setup: annual basis, out of sample, no run left out.
- **No cache.** The runs are solved on every build (about 2.5 minutes with 4 worker processes). Run keys don't include the code version, so a cached store could serve results of older code.
- **Path filters.** The workflow also runs when the code, lock or event set the bundle comes from changes: `packages/core/src/`, `packages/viz/src/`, their `pyproject.toml`, the root `pyproject.toml`, `uv.lock` and `parity/tests/data/thesis_eventset/`.
- **Reading it from a page.** `export-site` writes the bundle into `_site/bundles/explorer/` after `quarto render`, because the render empties `_site/`. A page reads it at run time with a relative URL, e.g. `FileAttachment("../bundles/explorer/manifest.json")` from `explorers/`. Locally, run the three commands at the top of the config, then serve `_site/` (below).

## Build

The workflow [`.github/workflows/site.yml`](../.github/workflows/site.yml) builds the site on every pull request that touches `site/`, the workflow, or the code and data of the explorer bundle (above), and builds and deploys it to GitHub Pages on `main`. It checks the fixture bundles against the SHA-256 in their manifests, solves and exports the explorer bundle, and checks it.

Locally, with the pinned Quarto CLI (1.10.19; `QUARTO_VERSION` in the workflow and `quarto-required` in `_quarto.yml`, change both together) and no system install, from the repository root on macOS:

```bash
V=1.10.19
mkdir -p results/quarto-dl
gh release download v$V -R quarto-dev/quarto-cli -D results/quarto-dl \
    -p "quarto-$V-macos.tar.gz" -p "quarto-$V-checksums.txt"
(cd results/quarto-dl && shasum -a 256 -c --ignore-missing quarto-$V-checksums.txt)
mkdir -p results/quarto-$V && tar -xzf results/quarto-dl/quarto-$V-macos.tar.gz -C results/quarto-$V
results/quarto-$V/bin/quarto render site
python3 -m http.server 8765 --bind 127.0.0.1 -d site/_site   # then open http://127.0.0.1:8765/
```

The output goes to `site/_site/`, ignored with Quarto's cache `site/.quarto/` (`site/.gitignore`). The pages load the bundles with `fetch`, so open them through a local server, not as `file://` URLs.
